## 1. 机制（已全部确认）

### 1.1 阵容

三个**战旗（War Banner）**：核心 / 中单 / 辅助。按**队伍**选，不是按人：

| 槽位 | 内容 | 计分人数 |
|---|---|---|
| 核心 | 某队的 1 号位 + 3 号位 | 2 人 |
| 中单 | 某队的中单 | 1 人 |
| 辅助 | 某队的 4 号位 + 5 号位 | 2 人 |

三支队伍可以相同也可以不同。两个结算期各自锁定（小组赛 8/11、国际邀请赛 8/19）。

⚠️ **「跨期继承」尚未证实，不要当成已知条件。** 唯一的文本依据是一条**通用键**：

```
DOTA_FantasyCraft_Tutorial_Locked_Body:
  "This period will be unlocked once matches begin for the preceding period.
   Your roster carries over period to period, so any improvements you make now
   will boost your performance later!"
DOTA_FantasyCraft_Tutorial_Upgrade_Body:
  "Your roster is eligible for an upgrade at the beginning of every period."
DOTA_FantasyCraft_PeriodLockedBody:
  "This will unlock after rosters are locked for the preceding period."
```

问题在于它**没有 2026 版本**。而本作里凡是有 `2026` 后缀覆盖的键（计分、rolling、
tutorial、基础说明）语义都被改过，所以一条只存在通用版的串很可能是**上一届的遗留文案**。
`{d:future_token_count} rolls available in future periods` 只说明代币分期发放，
不说明战旗状态继承。

✅ **2026-08-13 实测：继承。** 国际邀请赛期开出来的三面战旗，**前三枚与小组赛期收官时逐枚
相同**（核心 推塔2阶/吸血鬼、团战5阶/仁爱、GPM4阶/吸血鬼；中单、辅助同样），只是每面在后面
**追加了两枚新徽标，从 3 枚变成 5 枚**，代币重置为 30。所以小组赛期花掉的 40 枚代币收益是
双份的，那条通用键不是上一届的遗留文案。

⚠️ 仍未确认的是**第二期的计分结构**：`fantasy_model.py` 假设「正赛期场次取决于走多远，
没进淘汰赛的队整期 0 分」。若属实，第二期的选人逻辑和小组赛期完全不同 ——
要押能走深的队，而不是单局产出最高的队。这条必须在 8/19 锁定前定下来。

### 1.2 战旗结构 —— 3 枚徽标，链式相邻

**修正**：上一版把徽标数量和布局列为「阻塞项」。截图已给出，且用九枚徽标的数字逐一验算通过。

```
每面战旗恰好 3 枚徽标，竖排。相邻关系是链：  ①—②—③
① 和 ③ 不相邻。中间那枚有两个邻居，两端各只有一个。
```

颜色分布**由定位决定，不可修改**：

| 定位 | 位置① | 位置② | 位置③ |
|---|---|---|---|
| 核心 | 🔴红 | 🟢绿 | 🔴红 |
| 中单 | 🔴红 | 🔵蓝 | 🟢绿 |
| 辅助 | 🔵蓝 | 🟢绿 | 🔵蓝 |

**颜色 → 可选统计项（各 6 项）：**

| 颜色 | 统计项 |
|---|---|
| 🔴 红 | 击杀、死亡、正反补、GPM、狂石、推塔 |
| 🔵 蓝 | 假眼、堆野怪、拾神符、占领观察者、诡计之雾、采集莲花 |
| 🟢 绿 | 肉山、团战参与、眩晕、痛苦魔方、第一滴血、杀信使 |

同一战旗上不会有重复统计项，重选统计项**保证换成不同的一项** →
某颜色有 k 枚徽标就只能同时持有该颜色 6 项中的 k 项，重选池大小恒为 6−k。

### 1.3 倍率：加法叠加

**修正**：上一版没确定品质和特性怎么合成。UI 键 `TotalStatBonusDesc` = "Total combined
score of Quality and Trait"，且截图九枚徽标全部满足：

```
徽标倍率 = 100% + 品质% + 该徽标受到的特性净值%
```

**品质**：第1阶 +10% / 第2阶 +30% / 第3阶 +60% / 第4阶 +100% / 第5阶 +150%。
本地化注明「加成越大越稀有」，具体权重未知。

**特性**（7 种，含「基础」）：

| 特性 | 效果 | 三枚战旗下的含义 |
|---|---|---|
| 分形 Fractal | 三枚品质**互不相同** → +60% | 两枚同阶就归零 |
| 仁爱 Benevolent | 给**相邻**各 +20%，自己 0 | 放中间产出 +40%，放两端 +20% |
| 吸血鬼 Vampiric | 自身 +50%，相邻各 −10% | 放**两端**最优 |
| 唯一 Unique | 若是战旗上唯一的「唯一」→ +30% | 放 1 枚即无条件 +30% |
| 友好 Friendly | ≥3 枚友好 → 各 +50% | 3 枚战旗 ⇒ 必须三枚全是 |
| 不可腐蚀 Incorruptible | 低于第3阶按第3阶算 | 等价于品质保底 +60% |
| 基础 Base | 无 | — |

**修正**：上一版认为中文的「分形」是 Incorruptible 的误译。**判错了** ——
Fractal 和 Incorruptible 是两个独立特性，同时存在。

### 1.5 重选代币

- **小组赛期 40 枚，后续阶段另发 30 枚**，合计 70。可付费购买。
- 任何操作消耗 1 枚。**永远只有 3 个可选操作**，对所有战旗相同；用掉一个后全部刷新。
- 花 1 枚可以只刷新选项。
- ⚠️ **若当前战旗没有该颜色的徽标，对应选项灰掉不可用** ——
  同一个选项对三面战旗的价值不同，可以挑战旗用。

**完整操作空间**（2026-08-03 从完整客户端本地化 `dota_english.txt` 取得。
注意目标串的键前缀是 `DOTA_Fantasycraft_`（小写 c），和其余的 `DOTA_FantasyCraft_` 不同，
之前的 526 行摘录里没有它们）：

**4 个带目标的动词**：提升品质 `IncreaseQuality` / 重选品质 `RollQuality` /
重选特性 `RollShape` / 重选统计项 `RollStat`

**17 个目标**：

| 类别 | 目标 |
|---|---|
| 指定 | 由你选的一枚（Choose an Emblem） |
| 全部 | 所有徽标 |
| 整色 | 红色全部 / 蓝色全部 / 绿色全部 |
| 第一枚 | 第一枚（不分色）/ 第一枚红 / 第一枚蓝 / 第一枚绿 |
| 最后一枚 | 最后一枚（不分色）/ 最后一枚红 / 最后一枚蓝 / 最后一枚绿 |
| 随机 | 随机一枚（不分色）/ 随机一枚红 / 随机一枚蓝 / 随机一枚绿 |

**2 个不带目标的**：随机提升一个品质 / 随机提升两个品质并降低一个

✅ **2026-08-08 实测：「提升 / 降低品质」是带方向的重选，不是走一格。** 核心战旗上
用掉一次「随机提升两项品质并降低一项」，结果是 **推塔 第5阶→第1阶、团战 第2阶→第4阶、
GPM 第2阶→第4阶** —— 一次跨了 4 阶和 2 阶。所以正确的模型是：被选中的三枚各自
**重选一个新阶数**，两枚约束在比原阶高的一侧、一枚约束在低的一侧，阶数分布仍是
那个「加成越大越稀有」的未知分布。

推论（对代币策略影响很大）：**这个操作对已经养出高阶徽标的战旗是有实质下行的**。
第5阶徽标一旦被抽中当「降低」的那一枚，可以直接掉到第1阶（150% → 10%）。
按「温和递减」假设，当时那面战旗的事前 E[Δ] 是 +2,037、变好概率 89%，我们摇进了
那 11%，实际 −558。决策没错，是运气；但把它当成「稳赚」是错的。

⇒ 徽标类操作共 **4 × 17 + 2 = 70 种**。

称号类：生成新称号选项（`GenerateTitles`，1 代币）。
`ChoosePlayer` / `DraftPlayer` / `RollPlayerRegion` 是 2025 版按**选手**选人的遗留串，
2026 改成按队伍选，且 **更换队伍是免费的**
（`Tutorial2026_ViewTablet_Body`: "You may **freely** change the chosen team"），
所以这三条大概率不在本届的操作池里。

**位置退化**（因为战旗只有 3 枚）：

| 定位 | 颜色类目标的实际效果 |
|---|---|
| 中单（红蓝绿各 1） | **每种颜色只有一枚** ⇒ 整色 / 第一枚 / 最后一枚 / 随机 全部退化成同一枚，颜色类操作在中单上是**完全精确**的 |
| 核心（红绿红） | 第一枚红 = 位置①，最后一枚红 = 位置③，随机红 = 五五开；绿色类目标精确指向位置② |
| 辅助（蓝绿蓝） | 同上，蓝绿互换 |

⚠️ 还不知道的是这 70 种在 3 个选项里的**抽样权重** —— 这是代币策略的核心输入。

### 1.6 计分流程

**修正**：上一版把「取最高两局是相加还是平均」列为待确认。旧版英文串明写 "add the top two"。

```
每局，每名选手：Σ(战旗上三项统计 × 基础分 × 徽标倍率) × (1 + 称号加成%)
  → 同一槽位内所有选手取平均        = 该局该槽位得分
  → 一个系列赛内取总分最高的两局，相加
  → 一期内若打了多个系列赛，取最高的那个系列赛
```

**排序单位是「局」，不是「统计项」** —— 即 `max2(sum)`，不是 `sum(max2)`。
这一条决定了整个建模方式，见 `docs/06-banner.md`。

## 2. 目标函数 —— 和预测题本质不同

梦幻得分不直接换算积分，而是**和所有其他玩家比排名**，按百分位给分。
奖励档位（`DOTA_Fantasy26_RewardTierName0..8`）：**100 / 99 / 95 / 90 / 80 / 60 / 40 / 20 / 10** 百分位，
与截图的 12,000 / 11,400 / 10,000 / 8,400 / 5,800 / 3,300 / 1,700 / 400 / 200 一一对应。
（`DOTA_Fantasy25_*` 那套 0/25/50/75/90/95/99/99.9 是**上一届**的，不适用。）
结算期只有两个：`DOTA_Fantasy26_PeriodName0 = Group Stage`、`PeriodName1 = The International`。

目标是 **max E[f(percentile)]**，f 强凸。三个关键差异：

**(a) 这是对抗性博弈。** 得分取决于我相对于其他玩家。若最优阵容显而易见，
所有人都选它，百分位就由噪声决定。**要进 99 百分位，可能必须偏离大众选择。**

**(b) 一大部分方差是外生的。** 徽标的品质/特性是随机 roll 的，只能通过代币策略部分控制。

**(c) 决策是序贯的。** 代币分期发放（40 + 30），小组赛打完后信息更多。
若战旗跨期继承（**待证实**，见 §1.1），现在花代币的收益翻倍，该激进；若不继承，
小组赛期的代币只买一期收益，该保守。**这是目前对代币策略影响最大的一个未知。**

我们能控制的：① 选哪三支队 ② 三面战旗各选哪三项统计 ③ 代币怎么花 ④ 教练称号。

## 3. 数据

### 3.1 18 项统计的可得性（2026-08-02 重新核实）

| 状态 | 项目 |
|---|---|
| ✅ 直接有（13） | 击杀、死亡、正反补、GPM、推塔、假眼、堆野怪、拾神符、肉山、团战参与、眩晕、第一滴血 |
| ✅ 从 json 解析（3） | 杀信使 `killed.npc_dota_courier`、痛苦魔方 `killed.npc_dota_miniboss`、诡计之雾 `item_uses.smoke_of_deceit` |
| ✅ 代理（1） | 狂石 → `item_uses.madstone_bundle`（见下） |
| ❌ **拿不到（2）** | **占领观察者、采集莲花** |

**狂石**：Valve 的内部键名是 `NeutralTokensFound`，对应 OpenDota 的 `neutral_tokens_log` ——
该字段在当前版本的所有解析里都是空数组（查了 6 场近期职业局，parser v22）。
但 `item_uses.madstone_bundle` 有值（32,709 行里 25,775 行非零），量级合理
（核心 16.2/局、中单 11.8、辅助 2.1），已作为代理接入。
**而且它不重要** —— 按 13 分算只值 210 / 153 / 27 分，是三个定位下的红色垫底项。

**观察者 / 莲花**：拉了一场**完整解析**的职业局（player 对象 143 个字段），
把整个 JSON 含 `objectives`、`chat`、`teamfights` 一起 grep：`lotus` 0 次、`watch` 0 次、
`outpost` 0 次。**不是少请求了一列，是 OpenDota 的解析器根本不产出这两个事件。**
重拉、换 endpoint 都无用。

缺口位置很不巧 —— 两个洞都在**蓝色**，而蓝色是辅助战旗的主色（2 枚蓝 + 1 枚绿）：

| 定位 | 蓝色已知四项的均值（分/局） |
|---|---|
| 核心 | stacks 611 · runes 440 · smokes 50 · wards 43 |
| 中单 | runes 1,400 · stacks 451 · wards 176 · smokes 23 |
| **辅助** | **wards 1,024 · smokes 904 · stacks 888 · runes 411** |

核心和中单无所谓（蓝色本来就是它们的垃圾色）。辅助是真问题：
未知项只要达到 **2.8 个观察者/局 或 2.3 朵莲花/局** 就该挤掉 runes，
这对 4/5 号位完全在射程内。V 社默认给的辅助战旗上放的正是占领观察者（210% 倍率）。

补洞的四条路，按性价比：① 客户端若显示选手各项均值则直接解决 ②STRATZ API（需 token）
③ 自己解析 replay（`replay_url` 可得，彻底但重）④ 结构先验 + 敏感性分析。
