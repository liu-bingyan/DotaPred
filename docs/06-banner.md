## 1. 目标函数：`max2(sum)`，不是 `sum(max2)`

计分规则排序的单位是**局**，不是统计项。本地化三处一致：

```
"...to decide the final score for A GAME. The TOP TWO SCORING GAMES within a
 series are used to get the role's final score."          (ScoringDetails2026)
"...will use the two highest scoring GAMES within that series."  (BestSeriesTooltip)
"A player's score is based on their best 2 GAMES within a series."
```

所以要优化的是

```
V(S) = E[ max over series ( 该系列赛内总分最高两局之和 of  Σ_{s∈S} w_s · x_s ) ]
```

**这个量不能按统计项分解。** 三个候选目标里：

| 做法 | 判定 |
|---|---|
| `Σ EV(每项)` | 精确等于 `E[单局总分]`，但漏掉了取最大带来的项，那一项依赖总分的方差和形状。只有当所有候选项的方差和协方差都相同时才等价 |
| `Σ max2(每项)` | **严格错误**。恒有 `Σ_s max2(x_s) ≥ max2(Σ_s x_s)`，等号只在三项峰值落在同一局时成立 → 系统性高估「好局互不重叠」的组合，正好是该避开的 |
| `max2(联合总分)` + 枚举 | ✅ 正确 |

### 1.1 联合分布不用估

关键便宜：**每一局历史比赛本身就是 18 项统计的一次联合抽样**。
按**整局** bootstrap（而不是按统计项各自抽），相关性、非线性依赖全部原样保留，
不需要协方差矩阵、copula 或任何分布假设。

实现：每个槽位存一个 `X` 矩阵（局数 × 18），任意组合的单局分 = `X @ 指示向量`；
所有组合**共用同一批随机局号**（common random numbers）→ 组合之间是配对比较，
蒙特卡洛噪声几乎全部抵消，比加大 `n_sims` 有效得多。

### 1.2 模拟结构

- 系列赛长度：实测 2,144 个完整职业 Bo3 中 **61.8% 打两局，38.2% 打三局**。
  打三局时取最好两局（`g1+g2+g3 − min`）。
- 一期内的系列赛数由小组赛名次决定：4-0→4 场、4-1→5、淘汰赛胜/败→6、1-4→5、0-4→4。
  名次分布来自 `data/sim_buckets_boot.npy`。
- **按胜负分池抽样**：赢的系列由两个胜局（+ 打满时一个负局）组成，输的系列相反。
  必要，因为产出强烈依赖结果（核心赢的局高 28%、中单高 41%、辅助低 1%）。

### 1.3 可分性

一期总分 = 三个定位各自「最好系列赛」之和，每个定位独立取最大 →
**三个槽位可以各自优化再拼起来**，不用跑 16³。
（只有做百分位对抗时才需要联合，因为那时总分分布的形状才重要。）

## 3. EV 法错在哪里 —— 定量

**48 个槽位里 34 个一致，平均损失 0.76%，最大 5.32%**（Aurora 辅助）。
分定位：核心 11/16、中单 9/16、辅助 14/16。

分数差距不大，但它改变了一个**系统性判断**：

| | 按 EV 排 | 按 max2(sum) 排 |
|---|---|---|
| 核心红色第二枚 | 死亡 ×8 / 正反补 ×8 | **正反补 ×13** / 死亡 ×3 |
| 中单红色 | 死亡 ×10 / GPM ×5 / 正反补 ×1 | 死亡 ×10 / **正反补 ×6** / GPM ×**0** |

### 3.1 原因一：天花板

| 统计项 | 上限 | 实测最大值 |
|---|---|---|
| 死亡 | **1,950（零死亡）** | 1,950 |
| 团战参与 | ≈2,124 | 2,124 |
| GPM | 软上限 | 2,324 |
| 正反补 | 无 | **4,887** |
| 堆野怪 | 无 | **4,680** |
| 激活神符 | 无 | 4,089 |
| 假眼 / 诡计之雾 | 无 | 3,159 / 3,223 |

死亡的均值好看（核心 1,100–1,370），但它**永远不可能超过 1,950**，且左偏（最低 −1,560）。
在连续取最大的规则下，**有硬顶的项被系统性高估**。

### 3.2 原因二：方差太小等于没有贡献

GPM 的标准差只有 180–270，别的红色项是 400–540 —— 因为 GPM 是速率量，不随时长累积。
在「取最好」的规则里它几乎不贡献任何上行，所以中单红色位上 GPM 从 EV 法的 5 支队直接归零。
（核心位上 GPM 仍然入选 16/16，因为那里它的均值优势足够大，且有两枚红色可放。）

### 3.3 一个反直觉的推论

在 `max2(sum)` 下，只有**总分**的方差能吃到取最大的溢价，而
`Var(总分) = Σσᵢ² + 2Σcov`。所以**互不相关的统计项会互相抵消方差，反而降低溢价**；
**同涨同跌的项**才能把总分的尾巴撑起来。选词条时该找和其他两枚**正相关**的 ——
和常规的组合分散直觉正好相反，因为我们要的不是稳定，是一个足够高的最大值。

## 4.5 两项输入一直是错的（2026-08-13 修正）

拿 Valve 录像解析出来的逐局统计（`scripts/import_replay_stats.py`）和我们从 OpenDota
推的数字在**石油杯 176 场 / 1,390 个选手-局**上逐项对账（`scripts/validate_replay_stats.py`）：

| 统计项 | 我们的均值 | Valve 均值 | 比值 | 相关 | 诊断 |
|---|---:|---:|---:|---:|---|
| 狂石 | 10.83 | **34.56** | 0.31 | 0.988 | 用 `madstone_bundle` 的**使用次数**当拾取数，纯尺度错误 |
| 痛苦魔方 | 0.18 | **0.57** | 0.32 | 0.575 | 只算 `npc_dota_miniboss` 的击杀归属者，Valve 算参与者 |
| GPM | 534.03 | 543.08 | 0.983 | 0.996 | OpenDota 的 `gold_per_min` 与 Valve 的 `m_iTotalEarnedGold` 口径差 1.7% |

其余 13 项**逐行完全相同**。**团战参与相关 1.000、98% 逐行相同** —— 本文 §0 把它列为
最高风险的未校准输入，`fetch_stratz_fights.py` 整个脚本就是为了校准它，结论是不用校准，
OpenDota 的数就是 Valve 的数。

按正确值，狂石单局 34.56 × 13 = **449 分**（和推塔的 405 同档），痛苦魔方
0.57 × 879 = **501 分**。这两项在本文的词条排序里一直垫底，是因为输入少算了三倍 ——
**§0 那张表里凡是把狂石或痛苦魔方排除掉的结论都要重跑**。

另外，莲花和占领观察者在 OpenDota 和 STRATZ 都不存在（2026-08-13 查过 STRATZ 全 schema），
只有录像解析有。TI 期辅助战旗第⑤枚就是莲花 250%，本文 §5.1 那条「辅助组合空间只有 36 种、
本该是 90 种」的局限现在可以解除。

## 5. 局限

1. **辅助的组合空间只有 36 种，本该是 90 种** —— 观察者、莲花缺席，
   而 V 社默认给的辅助战旗上就有占领观察者（210% 倍率）。见 `05-fantasy.md` §3.1。
2. **权重全设 1，所以同色徽标可交换。** 第二步权重不等时（一枚第5阶 +150%、一枚第1阶 +10%），
   核心红色从 C(6,2)=15 变成 6×5=30 种**有序**分配，而且高方差的项要放到高权重那枚上 ——
   这个耦合会重新洗牌。第一步的产出不是「最终答案」，是那个 `X` 矩阵和模拟框架。
3. 数字是 100% 基准的裸分，实际会被 130%–210% 的倍率放大。
4. 称号层未纳入。

## 4.6 品质重摇的落点分布：实测排除均匀分布（2026-08-17）

`roll_quality` 类操作把徽标的阶数重摇成什么，是所有品质决策的唯一自由参数。
`banner_craft.QDIST` 里挂了三个候选（均匀 / 温和递减 / 陡峭递减），默认温和递减。

从 `data/roll_options_log.json` 的 `banner_states` 里把 `via.op` 以 `roll_quality`
开头的快照前后对比，得到 8 次**徽标级**的实测落点：

| via | 战旗 | 阶数变化 |
|---|---|---|
| `roll_quality/first_ruby` | 核心 | 1 → 2 |
| `roll_quality/emerald` | 中单 | (2,1) → (1,2) |
| `roll_quality/emerald` | 中单 | (1,2) → (2,1) |
| `roll_quality/emerald` | 中单 | (2,1) → (1,3) |

落点序列 **1,2,2,1,2,1,2,3 —— 8 次里 0 次 4 阶或 5 阶**。

各候选分布下「连续 8 次全 ≤3 阶」的概率：

| 分布 | P(≤3阶) | P(8 次全 ≤3阶) |
|---|---|---|
| 均匀 | 0.60 | **1.7%** |
| 温和递减 | 0.78 | 13.7% |
| 陡峭递减 | 0.89 | 39.0% |

⇒ **均匀分布可以排除**（p≈0.017）；数据温和地偏向陡峭递减。默认的温和递减是
可用的折中，但对 `roll_quality` 是**偏乐观**的一侧 —— 报出来的 E[Δ] 应视为上界。

两点加强这个结论的观察：

1. 8 次里**没有一次摇到原阶不变**。任何分布下 P(不变) 都有 0.2~0.3，8 次期望
   ~2 次。这提示重摇是**强制换阶**的（与 §1.5 的 `increase_two_decrease_one`
   定向重摇同一族机制）。
2. 若确实强制换阶，则观测样本是「排除了原阶之后」的条件抽样。当时的原阶大多是
   1~2 阶，排除低阶会把样本分布往**高**处推 —— 而实测仍然全部堆在底部，说明
   无条件分布比原始计数显示的还要更靠下。

**实用推论：** 重选品质在高阶徽标上几乎永远是负期望，这不是牌面差，是动词本身
贵。只有当目标徽标停在 1~2 阶、且该徽标的统计项权重高时才值得考虑。

## 4.7 「随机提升一项品质」只在未满阶的徽标里抽（2026-08-17）

悬了很久的一个参数：`increase_one_quality` 是在**全部** n 枚里均匀抽（抽到 5 阶就空放），
还是只在**未满阶**的里抽？两者差 n/(未满阶数) 倍 —— 5 枚里 2 枚满阶时是 1.67×。

**观测：** 客户端在这个选项上把候选徽标用黄框标出来，框住的恰好是所有 <5 阶的徽标：

| 战旗 | 黄框 | 没框 |
|---|---|---|
| 核心 | 击杀①、眩晕③、GPM④ | 团战⑤、狂石⑤ |
| 中单 | 拾神符④、GPM③、第一滴血③ | 正反补⑤、团战⑤ |
| 辅助 | 第一滴血③、拾神符②、堆野怪④ | 莲花⑤、团战⑤ |

⇒ **在未满阶里均匀抽**，满阶徽标根本不进抽签。`untargeted()` 已改为按 `len(elig)` 归一。

同一条推论套用到 `increase_two_decrease_one`：要降的那枚必须 >1 阶、要升的两枚必须 <5 阶，
`picks` 只在可动的分配上均匀抽。改之前是在全部 `n*C(n-1,2)` 种分配上抽、抽到不可能的方向
就让整支概率蒸发（总质量 <1，残量被当成空放）—— 这**系统性低估**了升两降一。
改完两个操作的分支概率都严格和为 1（已断言）。

**实用推论：** 战旗越接近满阶，「随机提升一项品质」反而**越值钱**（分母变小），
和直觉相反。它也是牌面上唯一一个下行为零的动词。
